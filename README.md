## 🎯 Project Overview

**ProcureGuard** is a complex enterprise procurement application built on the **SAP ABAP RESTful Application Programming Model (RAP)** — Managed Business Object pattern — with **SAP Fiori Elements** for a zero-custom-code UI and **SAP HANA AMDP** for push-down analytics.

The system manages the full lifecycle of Purchase Requisitions: from creation with draft handling and live validations, through a multi-level approval workflow (Manager → CFO), all the way to automatic Purchase Order generation via `BAPI_PO_CREATE1`. At every step, the **Anthropic API** (Claude Sonnet & Haiku) is called directly from ABAP via HTTP to provide intelligent risk scoring, vendor risk narratives, duplicate detection, and executive summaries.

This project is designed as a **learning reference** for developers looking to master enterprise-grade RAP patterns including: complex actions, determinations, feature control, AMDP push-down, and AI integration — all in a realistic, end-to-end business scenario.

## ✨ Key Features

### Core Procurement
- 📝 **Draft-enabled forms** — full create/edit/delete with optimistic locking
- 🔄 **Multi-level approval workflow** — Manager → CFO → Auto-PO via SAP Flexible Workflow
- 📦 **Line item management** — composition child entity with inline editing and auto-positioning
- 🔗 **Purchase Order generation** — deep RAP action calling `BAPI_PO_CREATE1`

### Business Logic (RAP)
- ✅ **10 validations** — budget check, vendor block/dispute, status transitions, material master, authority check
- ⚙️ **7 determinations** — header total, PR ID auto-generation, line positions, budget KPI refresh
- 🔒 **Feature control** — field editability and action availability driven by status and user role

### HANA Analytics (AMDP)
- 💰 **Real-time budget remaining** — push-down aggregation from FI posting documents
- ⚠️ **Vendor risk scoring** — weighted multi-factor formula executed in HANA
- 🔍 **Duplicate PR detection** — HANA fuzzy text search across open requisitions
- 📊 **YTD spend aggregation** — vendor/material group analytics from MM/FI tables

### AI Integration (Anthropic API — Direct)
- 🤖 **Vendor risk narrative** — plain-language risk explanation generated by `claude-sonnet-4-5`
- 💡 **Alternative vendor suggestions** — AI recommends lower-risk sourcing alternatives using `claude-haiku-4-5`
- 📄 **Smart executive summary** — one-click approver briefing for complex PRs via `claude-sonnet-4-5`
- 🔁 **Duplicate explanation** — AI explains why two PRs are semantically similar using `claude-haiku-4-5`

### Security
- 🛡️ **PFCG role-based access** — 5 roles: Requestor, Manager, CFO, Buyer, Admin
- 🔐 **Custom auth objects** — `ZPROCAUTH` (plant/purchasing group) and `ZPROCAMNT` (amount authority)
- 🧩 **RAP feature control** — dynamic field and action enablement per user and status

## 🚀 Getting Started

### Prerequisites

| Requirement | Version |
|---|---|
| SAP S/4HANA or BTP ABAP Environment | 2022+ (FPS00) |
| SAP HANA | 2.0 SPS05+ (for AMDP fuzzy search) |
| Eclipse ADT | Latest (3.x) |
| SAP BTP Account | Trial or productive (for AI features) |

### 1. Clone / Import into ABAP System

Import all transport requests in the correct sequence:

```
1. ZPROCUREMENT_K900001  →  DDIC (tables, domains, data elements)
2. ZPROCUREMENT_K900002  →  CDS Views (ZI_* interface views)
3. ZPROCUREMENT_K900003  →  RAP BO (BDEF, BIL, projection views)
4. ZPROCUREMENT_K900004  →  Service Definition & Binding
5. ZPROCUREMENT_K900005  →  AMDP Classes
6. ZPROCUREMENT_K900006  →  AI Integration Classes
```

### 2. Configure Number Range

```
Transaction SNRO → Object: ZPR_RANGE
Set interval: 0000000000000000001 to 9999999999999999999 (internal)
```

### 3. Configure Anthropic API Destination

```
Transaction SM59 → Create HTTP destination: ANTHROPIC_API
  Host:           api.anthropic.com
  Port:           443
  SSL:            Active (HTTPS)
  Authentication: None (API key passed in ABAP header)
```

Store your Anthropic API key in the ABAP secure store:

```abap
" Run once during setup — stores key securely
cl_abap_gcts_secrets=>set_secret(
  iv_secret_name  = 'ANTHROPIC_API_KEY'
  iv_secret_value = '<your-anthropic-api-key>' ).
```

Maintain model names in customizing table `ZPROCUREMENT_AI_CONFIG`:

| Key | Value |
|---|---|
| `DEFAULT_MODEL` | `claude-sonnet-4-5` |
| `FAST_MODEL` | `claude-haiku-4-5-20251001` |
| `API_ENDPOINT` | `https://api.anthropic.com/v1/messages` |
| `API_KEY_SECRET` | `ANTHROPIC_API_KEY` |

### 4. Assign PFCG Roles

```
Transaction SU01 → Assign one of:
  ZPROCUREMENT_REQUESTOR   →  Standard requestor users
  ZPROCUREMENT_MANAGER     →  Procurement managers
  ZPROCUREMENT_CFO         →  Finance / CFO approvers
  ZPROCUREMENT_BUYER       →  Purchasing buyers
  ZPROCUREMENT_ADMIN       →  System administrators
```

### 5. Launch the Fiori App

```
Transaction /IWFND/MAINT_SERVICE → Activate ZPROCUREMENT_ODATA_V4
Open in browser: /sap/bc/ui5_ui5/sap/zprocurement/
```

Or preview directly in ADT: right-click `ZPROCUREMENT_ODATA_V4` → **Preview**.

## 🔢 AMDP Procedures

All computationally intensive analytics are pushed down to HANA via AMDP, avoiding data transfer to the application server.

| Class | Method | Input | Output |
|---|---|---|---|
| `ZCL_PROC_AMDP_BUDGET` | `CALC_BUDGET_REMAINING` | Cost Center, Fiscal Year | Budget total, consumed, remaining, utilization % |
| `ZCL_PROC_AMDP_VENDOR_RISK` | `CALC_VENDOR_RISK_SCORE` | Vendor ID | Weighted risk score (0–100) from 5 factors |
| `ZCL_PROC_AMDP_DUPLICATE` | `DETECT_DUPLICATE_PRS` | Justification text, Vendor, Material Group | List of similar PRs with similarity score |
| `ZCL_PROC_AMDP_SPEND` | `AGGREGATE_SPEND_YTD` | Vendor, Cost Center, Fiscal Year | YTD spend total, PO count, avg order value |

**Risk Score Weighting (AMDP):**
```
On-time delivery rate    → 35%
Open dispute cases       → 25%
Payment terms compliance → 15%
Single-source dependency → 15%
Country / geographic risk→ 10%
```

## 🤖 AI Integration

All AI features call the **Anthropic API directly** from ABAP via HTTP — no SAP BTP AI Core subscription required. The base class `ZCL_AI_PROCUREMENT_SERVICE` handles authentication, request building, and response parsing. All other AI classes simply call it, making the integration layer completely swappable.

### How It Works

```
RAP Action Handler
      │
      ▼
ZCL_AI_RISK_ANALYZER / ZCL_AI_SUMMARY_GENERATOR / ...
      │  (calls)
      ▼
ZCL_AI_PROCUREMENT_SERVICE  ──── HTTP POST ────►  api.anthropic.com/v1/messages
      │                                                      │
      │  Headers:                                            │
      │    x-api-key: {from secure store}                    │
      │    anthropic-version: 2023-06-01                     │
      │    content-type: application/json                    │
      │                                                      │
      │  Body:                                               │
      │    { "model": "claude-sonnet-4-5",                   │
      │      "system": "...",                                │
      │      "messages": [{"role":"user","content":"..."}] } │
      │                                                      │
      ◄──────────── response.content[0].text ◄───────────────
      │
      ▼
Result persisted back to RAP entity / returned as action result
```

### Use Cases & Models

| Use Case | Trigger | Model | Output |
|---|---|---|---|
| Vendor Risk Narrative | `AI_ANALYZE` action | `claude-sonnet-4-5` | Plain-language risk summary stored on PR header |
| Alternative Vendor Suggestion | `FIND_ALTERNATIVES` (Risk = HIGH) | `claude-haiku-4-5-20251001` | Up to 3 alternatives with estimated price delta |
| Spend Anomaly Explanation | When AMDP flags outlier | `claude-haiku-4-5-20251001` | Human-readable anomaly explanation |
| Duplicate Explanation | When duplicate flag = TRUE | `claude-haiku-4-5-20251001` | Explanation of similarity with linked PR |
| Smart Executive Summary | `AI_SUMMARIZE` action | `claude-sonnet-4-5` | Approver briefing returned as popup (not persisted) |

### ABAP Integration Pattern

```abap
" ZCL_AI_PROCUREMENT_SERVICE — core HTTP call
METHOD call_anthropic_api.
  DATA(lo_client) = cl_web_http_client_manager=>create_by_http_destination(
    cl_http_destination_provider=>create_by_sm59( 'ANTHROPIC_API' ) ).

  DATA(lo_request) = lo_client->get_http_request( ).

  " Anthropic-specific headers
  lo_request->set_header_field( i_name = 'x-api-key'
                                 i_value = get_api_key( ) ).
  lo_request->set_header_field( i_name = 'anthropic-version'
                                 i_value = '2023-06-01' ).
  lo_request->set_header_field( i_name = 'content-type'
                                 i_value = 'application/json' ).

  " Request body — model in body, system as top-level field
  lo_request->set_text(
    |\{ "model":"{ iv_model }",| &&
    |"max_tokens":1000,| &&
    |"system":"{ iv_system }",| &&
    |"messages":[| &&
    |  \{"role":"user","content":"{ iv_prompt }"\}| &&
    |]\}| ).

  DATA(lo_response) = lo_client->execute( if_web_http_client=>post ).

  " Parse: response lives at content[0].text
  rs_result-text       = extract_json_path( lo_response->get_text( ) '/content/0/text' ).
  rs_result-tokens_in  = extract_json_path( lo_response->get_text( ) '/usage/input_tokens' ).
  rs_result-tokens_out = extract_json_path( lo_response->get_text( ) '/usage/output_tokens' ).
ENDMETHOD.
```

### Error Handling & Fallback

| Failure Scenario | Fallback Behavior |
|---|---|
| `api.anthropic.com` unreachable | Log error, set `AiRiskLevel = 'MEDIUM'`, PR processing continues |
| HTTP 429 Rate limit | Queue request in `ZPROCUREMENT_AI_QUEUE`, retry via background job |
| HTTP 401 Invalid API key | Raise `ZCX_AI_ERROR`, display config error message to admin |
| Response parsing error | Log raw response to `ZPROCUREMENT_AI_LOG`, return generic message |
| Timeout > 30s | Retry once, then skip AI step and flag for manual review |

### Data Privacy

- Only material numbers, amounts, vendor IDs, and scrubbed justification text are sent — no personal data
- Justification text is pre-processed by `ZCL_AI_PROCUREMENT_SERVICE` to strip emails, phone numbers, and employee names before sending
- Every API call is logged in `ZPROCUREMENT_AI_LOG` with timestamp, model, token counts, and a hash of the input — never the raw content
- AI features can be disabled per plant via customizing table `ZPROCUREMENT_AI_CONFIG`

## ⚡ RAP Actions & Validations

### Actions

| Action | Type | Available When | Description |
|---|---|---|---|
| `SUBMIT` | Instance | Status = DRAFT | Validates and triggers Flexible Workflow |
| `APPROVE` | Instance | Status = PEND_MGR / PEND_CFO | Advances approval step, triggers next level or PO creation |
| `REJECT` | Instance | Status = PEND_MGR / PEND_CFO | Captures reason via dialog, notifies requestor |
| `ESCALATE` | Instance | Status = PEND_MGR | Routes to next approver, resets SLA timer |
| `CREATE_PO` | Instance | Status = PO_CREATED | Deep action calling `BAPI_PO_CREATE1` for all line items |
| `AI_ANALYZE` | Instance | Status ≠ REJECTED | Computes and persists AI risk score + narrative |
| `AI_SUMMARIZE` | Instance | Status ≠ DRAFT | Returns executive briefing as popup |
| `FIND_ALTERNATIVES` | Instance | Risk Level = HIGH | Returns AI-suggested alternative vendors |

### Key Validations

| Validation | Severity | Description |
|---|---|---|
| `validateBudgetAvailability` | ❌ Error | Blocks if total exceeds available budget (AMDP-powered) |
| `validateVendorStatus` | ❌ Error | Blocks if vendor is blocked or has open dispute in LFA1/LFLAF |
| `validateApprovalAuthority` | ❌ Error | Blocks if user's approval limit is below PR total amount |
| `validateDuplicatePR` | ⚠️ Warning | Warns if AI/AMDP detects a similar open requisition |
| `validateStatusTransition` | ❌ Error | Enforces legal state machine transitions |
| `validateMaterialMaster` | ❌ Error | Validates each line item material in the target plant |

## 🤝 Contributing

Contributions are welcome! Please follow these guidelines:

**Branch Naming:**
```
feature/phase1-data-model
fix/validation-budget-check
docs/amdp-specification
```

**Transport Requests:**
- One transport request per phase or logical unit of work
- Always include description: `[Phase X] Short description`
- Never mix DDIC changes with program logic in the same request

**Code Style:**
- Follow [SAP ABAP Clean Code Guide](https://github.com/SAP/styleguides/blob/main/clean-abap/CleanABAP.md)
